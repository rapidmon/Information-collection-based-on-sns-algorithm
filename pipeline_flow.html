브리핑 생성 — generate_briefing

LLM은 검증(④)과 발행 확정분 작문(⑥)에만 사용
⚙️ 코드① 게시물 점수 산정 (카테고리별 상대평가)

점수 = 0.8 × AI 초안 + 0.2 × 인게이지먼트 백분위(플랫폼별 보정) → 카테고리 안에서 최고점 = 1.0으로 정규화

⚙️ 코드② 결정적 클러스터링 (같은 사건 병합)

한/영 별칭 통일(엔비디아→NVIDIA 등 50종) → 요약 토큰 유사도 → union-find 후보군 → 그룹 병합. 같은 입력이면 항상 같은 결과, LLM 0회

⚙️ 코드③ 사건 점수 집계 + 대표 카테고리 선택

카테고리별 구성 게시물 점수 top-3 평균 → 가장 높은 카테고리 하나로만 노출

🔮 gpt-4o-mini + 웹검색④ 신뢰도 검증 — 0.85+ 상위 후보만

주장 추출(LLM) → DuckDuckGo 검색(주장 최대 8건) → 교차 판정(LLM). 과반 반박된 클러스터는 스캠/허위로 제거

⚙️ 코드⑤ 발행 항목 확정

카테고리 내 상대점수 0.85 이상 + 카테고리당 최대 6개

🔮 claude-sonnet-4-6⑥ 발행 확정분만 headline/불릿 작문

배치 20개씩 1~3회 호출. "주체+행위+수치" headline + 불릿 ≤3개 작성, 기계적 병합에 섞인 무관 게시물 정리. 실패 시 결정적 초안(최고점 게시물 요약) 그대로 발행 — 탈락 토픽은 작문하지 않음

💾 Firestore⑦ 브리핑 문서 저장 (영구 보관)

BriefingItem: headline·불릿·점수·카테고리·원문 URL·채점 근거 스냅샷

⚙️ 코드후보 전체 briefed 마킹

탈락분 포함 — 다음 날 재클러스터링 방지(토큰 누수 차단)

🗑 즉시 삭제AI 중요도 ≤ 0.6 게시물 삭제
